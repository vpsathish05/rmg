All five forecast cards explained: ML models used, P10 / P50 / P90 confidence bands, and MAPE accuracy scores.

Understanding P10 / P50 / P90
P10
Pessimistic
Only 10% chance result falls below this. Worst realistic scenario.
P50
Most Likely
Model's best guess. 50% chance result is above or below this.
P90
Optimistic
Only 10% chance result exceeds this. Best realistic scenario.
Think of it like a weather forecast: predicted 25°C (P50), could be as low as 18°C (P10), or as high as 32°C (P90). The actual always lands somewhere in that range.
Understanding MAPE

MAPE = Mean Absolute Percentage Error - the average % by which the model was wrong on historical data. Lower is better. Under 10% is considered good for revenue forecasting.

MAPE = mean( |actual − predicted| / actual ) × 100 Example: Actual = $5,000,000 | Predicted = $4,780,000 Error = |5M − 4.78M| / 5M = 4.4% ✓
The Five Forecast Cards
1

Revenue Forecast

ML Models Used
Holt's Damped Linear Trend Linear Regression Ensemble 60/40
How it works
Step 1 - Reconstruct Revenue
No revenue table exists. Calculated from: Allocation % × Day Rate × Working Days per month across 30 months.
Step 2 - Calibrate with Actuals
Real actuals for Jan–Jun 2026 loaded from Excel. Median ratio (actual ÷ reconstructed) applied as correction factor.
Step 3 - Model A: Holt (60%)
Exponential smoothing with damped trend. Gives more weight to recent data. Trend slows over time - no runaway extrapolation.
Step 4 - Model B: Regression (40%)
Linear Regression: Revenue = (w1 × headcount) + (w2 × time_index) + b. More staff = more capacity = more revenue.
Step 5 - Ensemble & Confidence Bands
Blend models 60/40. Apply residual std to compute P10/P50/P90, widening 8% per month out.
Key Formulas
Ensemble = 0.60 × Holt_forecast + 0.40 × Regression_forecast spread = residual_std × (1.0 + 0.08 × month_index) P10 = P50 − 1.28 × spread P50 = Ensemble forecast P90 = P50 + 1.28 × spread
P10 / P50 / P90
Yes - used Bands widen 8% per month
MAPE
4.4%
Average error on 30-month training data. Excellent for revenue forecasting (anything under 10% is good).
Output: ~$59.4M/year, +71% YoY growth, P10/P50/P90 area chart
2

Cluster Revenue Split

ML Models Used
No ML model Weighted Arithmetic Exponential Decay Blending
How it works
Step 1 - Pipeline Cluster Weights
For each month with pipeline deals, compute each cluster's share of total pipeline revenue.
Step 2 - Fallback for Empty Months
Months with no pipeline data use exponential decay blending toward the long-run average weight.
Step 3 - Apply to Revenue
Multiply total P50/P10/P90 from Card 1 by each cluster's weight to get cluster-level revenue.
Key Formulas
Weight[cluster, month] = Pipeline_Rev[cluster] / Total_Pipeline_Rev Decay = e^(−0.3 × months_since_last_data) Blended_weight = Last_weight × Decay + Avg_weight × (1 − Decay) Cluster_P50 = Total_P50 × Cluster_Weight
P10 / P50 / P90
Inherited from Card 1 - no independent bands
MAPE
Not computed - distributes existing forecast, no independent prediction
Output: Stacked bar - 5 clusters × 12 months. Cluster 5 dominates at 34.7%
3

Resource FTE by Role

ML Models Used
Holt's Damped Trend (per role) Pipeline Demand Overlay
How it works
Step 1 - Historical FTE per Role
18 months of monthly billable FTE queried for each of the top 15 canonical roles.
Step 2 - Holt Trend per Role
Each role gets its own independent Holt damped trend forecast for 12 months.
Step 3 - Overlay Pipeline Demand
Pipeline FTE (probability-weighted) added at 50% weight - conservative since it's new additive demand.
Step 4 - Hiring Gap
Peak 12-month demand minus current supply at 80% utilisation target = how many to hire.
Key Formulas
blended_FTE = max(0, holt_forecast + pipeline_FTE × 0.50) hiring_gap[role] = peak_demand_12m − (current_headcount[role] × 0.80)
P10 / P50 / P90
Not used - single point estimate per role
MAPE
Not computed - Holt used as smoother, not evaluated for accuracy
Output: Bar chart FTE by role × 12 months + hiring gap list (~420 FTE/month)
4

Project Volume Forecast

ML Models Used
Holt-Winters Additive Seasonal 90 months training data
How it works

Most powerful model in the system - uses 3 components:

ComponentWhat it captures
LevelCurrent baseline project count (~35/month)
TrendGrowing or shrinking over time?
SeasonalityMonthly patterns - Q1 surge, August dip, Q4 push

Uses 90 months of data (Jan 2019 → Jun 2026) because detecting yearly seasonal patterns needs 2–3 complete annual cycles minimum.

Key Formulas
Model: Holt-Winters additive, period = 12 spread = residual_std × (1.0 + 0.05 × month_index) P10 = max(1, round(forecast − 1.28 × spread)) P50 = max(1, round(forecast)) P90 = max(P50, round(forecast + 1.28 × spread))
P10 / P50 / P90
Yes - used Bands widen 5% per month (gentler than revenue) Minimum 1 project always
MAPE
Not reported - residual std used for bands only
Output: Bar chart with P10/P50/P90 - ~430 projects/year with seasonal pattern
5

COE Supply / Demand Gap

ML Models Used
No ML model Arithmetic Supply Projection
How it works
Supply Side
Current COE headcount from employee_skills. Project forward using headcount growth trend minus attrition over time.
Demand Side
Pipeline deals mapped to COE via role_mapping. FTE demand = deal allocation × probability weight.
Gap & Hiring Recommendation
Gap = Supply − Demand per month. Negative = shortfall. Peak shortfall = hiring needed.
Key Formulas
projected_supply[month] = current_available + (monthly_hc_growth × coe_share × month) × (1 − attrition_rate × month/12) demand[coe][month] = Σ (deal_FTE × deal_probability) gap = projected_supply − demand hiring_need[coe] = ceil(peak_demand − available_supply)
Attrition Rate
attrition_rate = resignations_last_12m / total_active_employees (default: 5% if data unavailable)
P10 / P50 / P90
Not used - single gap value per COE per month
MAPE
Not computed - supply/demand accounting, not a statistical forecast
Output: Bar chart gap per COE + hiring recommendations (~21 hires total)
